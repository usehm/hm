# Full-stack app: Go + Postgres + Firebase Auth + shadcn/ui admin

## Starting a new app

Run the scaffold script; it copies a working template, fills in the names and runs `go mod tidy`:

    sh <skill folder>/scaffold.sh <target-dir> <app-name> <go-module-path>

Then verify before changing anything:

    cd <target-dir>
    make db                      # Postgres in Docker (docker compose)
    cd backend && go build ./... && go vet ./...
    cd ../admin && npm install && npm run build

Start the API with `make backend` (a background shell) and check `curl localhost:8080/healthz`.
With `AUTH_DEV_BYPASS=1` (the default in .env), `curl -H 'Authorization: Bearer dev' localhost:8080/api/items` works without Firebase.

## Layout and conventions

    backend/
      cmd/server/main.go           wiring only: config, pool, migrate, routes, graceful shutdown
      internal/config/             all settings from environment variables; fail fast on missing ones
      internal/db/migrations/      NNNN_name.sql, applied in order at start-up, never edited once shipped
      internal/db/queries/         sqlc queries (-- name: X :one|:many|:exec|:execrows)
      internal/db/sqlc/            generated by `make sqlc`; do not edit by hand
      internal/auth/               Firebase ID-token verification (needs only FIREBASE_PROJECT_ID)
      internal/api/                net/http handlers with Go 1.22 patterns ("GET /api/items/{id}")
    admin/
      src/components/ui/           shadcn/ui components (add more with `npx shadcn@latest add <name>`)
      src/lib/api.ts               typed fetch wrapper; sends the Firebase ID token as a bearer token
      src/lib/firebase.ts          Firebase web SDK; VITE_* settings in admin/.env
      src/pages/                   one file per screen

- Every API route except /healthz goes through `authed`, which verifies the token and upserts the user.
  Scope every query by the signed-in user's id; never trust ids from the client for ownership.
- Schema changes: add a new migration file, update queries, run `make sqlc`, then the handlers.
- Handlers return JSON; errors are `{"error": "..."}` with a fitting status; log internal errors, don't leak them.
- The admin talks to the API through Vite's /api proxy in development.
- Secrets (Firebase keys, database passwords) live in .env files that are git-ignored.

## Adding a feature end to end

1. Migration: `backend/internal/db/migrations/000N_<feature>.sql`.
2. Queries in `backend/internal/db/queries/`, then `make sqlc`.
3. Handlers and routes in `backend/internal/api/`.
4. `admin/src/lib/api.ts` types and calls, then a page or component under `admin/src/`.
5. Verify: `go build ./... && go vet ./... && go test ./...`, `npm run build`, and exercise the endpoint with curl.
